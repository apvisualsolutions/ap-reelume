# Matriz de funcionalidades / Feature matrix

Este es el registro canónico del alcance. Toda funcionalidad debe tener identificador, versión objetivo, estado, criterio de aceptación y evidencia enlazada antes de considerarse terminada.

This is the canonical scope record. Every feature must have an identifier, target release, status, acceptance criterion, and linked evidence before it can be considered complete.

## Estados / Statuses

| Estado / Status | Significado / Meaning |
|---|---|
| `DESIGN_APPROVED` | Diseño aprobado; todavía no implementado. / Design approved; not implemented yet. |
| `PLANNED` | Incluido en un plan de implementación aprobado. / Included in an approved implementation plan. |
| `IN_PROGRESS` | Implementación activa. / Implementation is active. |
| `BLOCKED` | Existe un bloqueo documentado con responsable y condición de desbloqueo. / A documented blocker, owner, and unblock condition exist. |
| `IMPLEMENTED` | Código completo; faltan una o más verificaciones. / Code is complete; one or more checks remain. |
| `VERIFIED` | Criterio demostrado mediante evidencia enlazada. / Acceptance is demonstrated by linked evidence. |
| `DEFERRED` | Pospuesto de forma explícita a una versión identificada. / Explicitly deferred to an identified release. |
| `OUT_OF_SCOPE` | Fuera del compromiso actual; requiere una nueva decisión. / Outside the current commitment; requires a new decision. |

## Versiones / Releases

| Versión / Release | Propósito / Purpose |
|---|---|
| `MVP` | Aplicación x64 instalable y útil para validar la colección real. / Installable, useful x64 application for validating the real collection. |
| `STABLE` | Primera publicación pública completa, incluida ARM64. / First complete public release, including ARM64. |
| `POST_STABLE` | Mejoras que no bloquean la primera publicación estable. / Improvements that do not block the first stable release. |
