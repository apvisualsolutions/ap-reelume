VideoLAN — LibVLC, its core and its plugins
===========================================

AP Reelume decodes and plays video through LibVLC. Two packages published by VideoLAN bring it in,
and both travel in this artifact unmodified:

    LibVLCSharp 3.10.0                  the managed binding                LGPL-2.1-or-later
    VideoLAN.LibVLC.Windows 3.0.23.1    libvlc.dll, libvlccore.dll,        LGPL-2.1-or-later for the
                                        and the plugins under plugins/     core; see the plugins below

Copyright © the VideoLAN project and its contributors.

Neither package carries a COPYING file, so nothing upstream supplies the texts and they are supplied
here: LGPL-2.1.txt covers the binding and the core, and GPL-2.0.txt covers the plugins that are
licensed GPL-2.0-or-later rather than LGPL — the x264 encoder behind libx26410b_plugin.dll is the
clearest example.

The GPL-2.0 text in this folder was taken from VLC's own tree rather than from a third party: the
package ships it as the string vlc_about.h compiles into libvlc, which is the licence VLC displays
for itself. It carries the "either version 2 of the License, or (at your option) any later version"
clause. Until 2026-09-13 that clause was what let a GPL-2.0-or-later plugin sit inside this program,
which was then GPL-3.0-or-later; the program now carries a licence of its own, so the clause no longer
resolves the question and the copyleft plugins are an open point recorded in the third-party notices.

Nothing in these binaries has been modified. They are the files VideoLAN publishes, placed in the
payload as separate dynamic libraries that the program loads at run time; replacing them with another
build of the same library is a matter of overwriting the files, and the program will use the
replacement as long as it is interface-compatible.

A note on the version numbers, because they are not the same number. The NuGet package is
VideoLAN.LibVLC.Windows 3.0.23.1, whose fourth digit is that package's own packaging revision.
libvlc.dll declares file version 3.0.23, and vlc 3.0.23 is the tree VideoLAN publishes source for;
there is no vlc-3.0.23.1. The corresponding source is therefore the 3.0.23 one.


Where to get the corresponding source
-------------------------------------

It travels with the release. Every release that carries these binaries also carries, as attachments
alongside them, the corresponding source archives:

    vlc-3.0.23.tar.xz           https://download.videolan.org/vlc/3.0.23/vlc-3.0.23.tar.xz
    LibVLCSharp-3.10.0.tar.gz   https://code.videolan.org/videolan/LibVLCSharp/-/archive/3.10.0/LibVLCSharp-3.10.0.tar.gz

That is the point of section 6(d) of the LGPL-2.1 and of the last paragraph of section 3 of the
GPL-2.0: where an executable is offered for download from a designated place, offering equivalent
access to copy the source from that same place is distribution of the source. The archives are
fetched during the release with their digests recorded in SHA256SUMS.txt, which the release signs, and
the digest of the VLC archive is checked against the one VideoLAN publishes for it.

The work that uses the library is this program itself. Its source is public at
https://github.com/apvisualsolutions/ap-reelume, though since 2026-09-13 under a licence of its own
rather than a free one, so LGPL-2.1 §6(a) is no longer the route. The route is the one that was
already true in fact: anyone who wants to modify LibVLC and use the result has the library's source
above, and does not have to relink anything, because the libraries are separate files this program
loads at run time and anybody may replace.
